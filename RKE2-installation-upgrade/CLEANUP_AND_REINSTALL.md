# RKE2 Cleanup and Reinstall Guide

## What Was Fixed

The playbook has been updated to properly handle RKE2 bootstrap tokens:

1. **Token Retrieval**: The control plane now retrieves the actual node token generated by RKE2
2. **Token Sharing**: The retrieved token is passed to agent nodes via Ansible facts
3. **Agent Configuration**: Workers now use the correct token for bootstrapping
4. **kubectl Setup**: Control plane now properly sets up kubectl with KUBECONFIG
5. **Better Sequencing**: Ensures control plane is fully ready before agents attempt to join

### Key Changes Made

- `rke2-install.yml`: Added token retrieval and proper role sequencing
- `roles/rke2-server/tasks/main.yml`: Enhanced token retrieval with retries
- `roles/rke2-agent/tasks/main.yml`: Improved wait logic and bootstrap verification

## Cleanup Steps (Run These First)

### 1. Clean the Control Plane
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 << 'EOF'
# Stop RKE2 server
sudo systemctl stop rke2-server

# Remove RKE2 data (WARNING: This will delete the cluster)
sudo rm -rf /var/lib/rancher/rke2/*
sudo rm -f /etc/rancher/rke2/config.yaml

echo "Control plane cleaned"
EOF
```

### 2. Clean the Worker Node
```bash
ssh -i ~/github/ec2.pem ubuntu@54.164.100.158 << 'EOF'
# Stop RKE2 agent
sudo systemctl stop rke2-agent

# Remove RKE2 data
sudo rm -rf /var/lib/rancher/rke2/*
sudo rm -f /etc/rancher/rke2/config.yaml

echo "Worker node cleaned"
EOF
```

## Fresh Installation

After cleanup, run the playbook:

```bash
# Install entire cluster
ansible-playbook -i inventory.ini rke2-install.yml -v

# Or install specific roles if needed
ansible-playbook -i inventory.ini rke2-install.yml --tags rke2-server -v  # Server only
ansible-playbook -i inventory.ini rke2-install.yml --tags rke2-agent -v   # Agents only
```

## Verify Installation

After the playbook completes:

### 1. Verify Control Plane
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 << 'EOF'
# Check cluster nodes
export KUBECONFIG=/etc/rancher/rke2/rke2.yaml
kubectl get nodes -o wide

# Check pods
kubectl get pods -A

# Check services
kubectl get svc -A
EOF
```

### 2. Verify from Local Machine
```bash
# Copy kubeconfig from control plane
scp -i ~/github/ec2.pem ubuntu@52.201.216.243:/etc/rancher/rke2/rke2.yaml /tmp/rke2.yaml

# Test kubectl from local
export KUBECONFIG=/tmp/rke2.yaml
kubectl get nodes
kubectl get pods -A
```

## Troubleshooting

### If workers still don't join:

1. Check control plane logs:
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 "sudo journalctl -u rke2-server -n 50 --no-pager | grep -i error"
```

2. Check worker logs:
```bash
ssh -i ~/github/ec2.pem ubuntu@54.164.100.158 "sudo journalctl -u rke2-agent -n 50 --no-pager | grep -i error"
```

3. Verify token on control plane:
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 "sudo cat /var/lib/rancher/rke2/server/node-token"
```

4. Verify connectivity:
```bash
ssh -i ~/github/ec2.pem ubuntu@54.164.100.158 "curl -sk https://10.0.1.221:6443/healthz"
```

### If kubectl doesn't work on control plane:

1. Check KUBECONFIG:
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 "echo \$KUBECONFIG && cat /etc/rancher/rke2/rke2.yaml | head -5"
```

2. Check file permissions:
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 "sudo ls -la /etc/rancher/rke2/rke2.yaml"
```

3. Manually test:
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 "sudo /var/lib/rancher/rke2/bin/kubectl --kubeconfig /etc/rancher/rke2/rke2.yaml get nodes"
```

## Expected Timeline

- Common role: ~5 minutes (downloads and installs RKE2)
- Server role: ~3-5 minutes (starts control plane, waits for API)
- Agent role: ~2-5 minutes (joins workers to cluster)
- **Total**: ~10-15 minutes

## After Installation

The control plane will have:
- `/usr/local/bin/kubectl` - ready to use
- `KUBECONFIG=/etc/rancher/rke2/rke2.yaml` - set in bashrc
- RKE2 cluster running with all default add-ons (CNI, DNS, metrics, etc.)

You can immediately run:
```bash
ssh -i ~/github/ec2.pem ubuntu@52.201.216.243 "kubectl get nodes"
```
